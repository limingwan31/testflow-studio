# 路线图与已知限制 / Roadmap and limitations

> 当前版本 `0.1.0` 是**参考原型**：用来讲清架构、数据契约和安全边界，不是生产级测试执行器。
> 路线图按「先跑通闭环、再接真机、再做产品化」排序，欢迎在
> [Discussions](https://github.com/limingwan31/testflow-studio/discussions) 里调整优先级。

## 已完成 / Shipped (0.1.0)

- 意图 → 工作流 → 执行 → 实测报告 → 版本复跑 的完整闭环
- 可插拔驱动层与命令白名单、四条安全护栏
- 可编辑工作流画布、循环与扫描、运行历史
- 中英双语界面与导出报告、深色/浅色主题
- Apache-2.0 开源脚手架、双语文档、Issue/PR 模板、CI 与冒烟测试

## 阶段规划 / Stages

| 阶段 | 主题 | 主要工作 | 为什么放这个位置 |
| --- | --- | --- | --- |
| **P1** | 接真机 | `VisaScpiAdapter` / `ModbusTcpAdapter` 实现；命令超时、忙设备、重试、断连恢复；`SYST:ERR?` 排空；假负载验证流程 | 先证明架构在真实设备上站得住，再谈功能 |
| **P2** | 产品化 | 用户与操作员权限、审计日志、结果数据库、不可变发布版本、原生 PDF / Excel 报告、多 run 趋势与漂移分析 | 这几项恰好是同类产品目前也缺的部分，是差异化空间 |
| **P3** | 智能化 | LLM 经 OpenTAP MCP 生成步骤；上传 datasheet 生成测试计划与覆盖矩阵；分支/并行/条件步骤类型 | 契约与安全边界稳定后再放模型进来 |
| **P4** | 规模化 | 多工位调度、序列导入导出（如 TestStand）、部署包、插件市场、仪器资产清单 | 有真实用户与数据后再做 |

## 已知限制 / Known limitations

| 限制 | 现状 | 影响 | 计划 |
| --- | --- | --- | --- |
| 只有模拟仪器 | `Drivers.执行()` 用确定性公式生成读数 | 不能控制真实设备 | P1，实现适配器 |
| 规则式规划器 | 正则解析中英关键词 | 复杂意图无法理解 | P3，保持接口替换为 LLM/MCP |
| 无用户权限与审计 | 无登录、无角色 | 不能用于受监管产线 | P2 |
| 无结果数据库 | 运行历史存 localStorage（最多 12 条） | 换设备/清缓存即丢失 | P2 |
| 版本非不可变 | 修订号递增，但快照可被覆盖 | 审计链不完整 | P2 |
| 无超时/重试/断连恢复 | 执行引擎顺序调用 | 真实仪器异常时可能挂起 | P1 |
| 不支持 DAQ 卡与硬实时 HIL | 无相关驱动与确定性时序 | 不适用于实时控制场景 | 暂不计划，需专门平台 |
| 报告格式有限 | CSV / Markdown / 浏览器打印 PDF | 无内置 PDF 生成器、无 Excel 图表 | P2 |
| 工作流 JSON 中文字段 | 契约稳定但国际贡献者不友好 | 需要阅读文档 | 若要国际化需一次带迁移脚本的破坏性变更 |
| 单页全局命名空间 | 为支持 `file://` 未使用 ES modules | 大型化后模块隔离不足 | 迁移到正式 Web 框架时自然解决 |

## 明确不做 / Non-goals

- 不打算替代 NI TestStand 这类成熟的产线测试执行器；本项目定位是**测试编写与工位执行**层。
- 不打算让语言模型直接、逐条地发送 SCPI 命令；模型只产出可审阅的结构化工作流。
- 不承诺任何特定仪器厂商的兼容性；能力定义由使用者按编程手册维护。
- 不提供硬实时保证，也不作为安全关键系统的控制部件。

## 参与 / How to help

最需要贡献的地方：

1. **驱动适配器**：任选一台你手上的仪器，实现一个真实适配器并补上安全清单验证记录。
2. **契约测试**：为工作流 JSON 与事件协议补边界用例（非法能力、空扫描、限值篡改、取消运行）。
3. **双语与可访问性**：补全未登录短语、检查浅色主题对比度、键盘操作与屏幕阅读器支持。
4. **文档**：把你重建这套架构时踩过的坑写进 `docs/`。

提交前请读 [CONTRIBUTING.md](../CONTRIBUTING.md)，并确认改动没有削弱
[SECURITY.md](../SECURITY.md) 里的四条安全护栏。
