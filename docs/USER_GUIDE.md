# 使用指南 / User guide

## 1. 打开工作台

**在线演示（可直接分享给他人）**：打开 **https://limingwan31.github.io/testflow-studio/** ，
不用克隆、不用安装。它由 GitHub Pages 静态托管，功能与本地 `index.html` 完全一致。
语言/主题偏好与运行历史只存在你自己浏览器的 `localStorage`，不会上传到任何服务器；
页面里的仪器全部是浏览器内的模拟驱动，不会连接真实设备，也没有后端服务。

**最简单（本地）**：双击项目根目录的 `index.html`。不需要安装、不需要联网、不需要启动服务。

**或者**用内置静态服务器（方便改代码时刷新）：

```bash
node scripts/serve.js
# 浏览器打开 http://localhost:8080
```

支持 Chrome、Edge、Firefox 等现代浏览器。项目使用传统 `<script>` 顺序加载，
`file://` 协议下也能正常工作。

## 3. 写测试意图

用一句自然语言描述，中文或英文都可以。规划器会提取以下要素：

| 要素 | 中文写法 | 英文写法 | 默认值 |
| --- | --- | --- | --- |
| 电压范围 | `5-20 V`、`5 到 20 V` | `5-20 V`、`from 1 to 10 V` | `5-20 V` |
| 步进 | `步进 1 V`、`步长 2 V` | `in 1 V steps`、`step 1`、`in steps of 1` | 无步进时取 4 个均匀点 |
| 过冲限值 | `过冲限值 200 mV`、`不超过 180 mV` | `limit 150 mV`、`overshoot under 180 mV` | `200 mV` |
| 负载电流 | `2.5 A 负载`、`0.5 A 负载电流` | `2.5 A load`、`at 0.5 A` | `2.5 A` |
| 通道 | `CH1`、`CH2` | `CH1`、`on CH2` | `CH1` |
| 时基 | `1 ms 时基` | `1 ms timebase` | `1 ms` |

**示例**：

```
扫 5-20 V 电源，在 CH1 捕获负载瞬态，过冲限值 200 mV，2.5 A 负载
VI 扫描 1 到 10 V，步进 1 V，0.5 A 负载电流，限值 150 mV
3V3 轨负载阶跃 9-20 V，通道 CH2，过冲不超过 180 mV，3 A 负载
Sweep 5-20 V supply, capture the rail transient on CH1, overshoot limit 200 mV, 2.5 A load
VI sweep from 1 to 10 V in 1 V steps at 0.5 A load, limit 150 mV
```

点「生成工作流」后，每次会生成新修订号（Rev A → Rev B → …），方便对比复跑。
输入框下方的三个胶囊按钮是中英示例，点击即可填入。

> 描述里出现 `瞬态` / `transient` / `过冲` / `overshoot` 会归为「PSU 负载瞬态测试」，
> 只写 `扫描` / `sweep` 会归为「电源 VI 扫描测试」。这只是演示用的命名推断。

## 4. 编辑工作流

画布上每个循环内的步骤都有四个小按钮：

| 按钮 | 作用 |
| --- | --- |
| ✎ | 编辑参数（把参数变成输入框，保存后立刻重绘） |
| ↑ / ↓ | 调整步骤顺序 |
| × | 删除步骤 |

`+ 步骤` 会展开一个表单：选**设备** → 选该设备支持的**能力** → 填参数 → 添加。
参数项由能力定义自动生成，命令模板也来自能力定义，不能在界面上手写 SCPI。

`步骤 JSON` 页签展示完整工作流对象。字段名是中文，这是刻意保留的稳定契约，
切换界面语言不会改变它（页签上方有说明）。

## 5. 运行与日志

点 **运行**：

1. 右侧自动切到「执行日志」，先输出注入的安全序列（`*RST`、设置保护、`SYST:ERR?`）。
2. 逐个扫描点执行：`Point 1/4 · 5 V` → 各步骤的命令与确认 → `过冲 138 mV · 下跌 …` →
   `PASS · 过冲 138 mV < 上限 200 mV · 限值锁定，AI 不可修改`。
3. 底部结果表格、波形与结论同步生成，进度条按点位推进。
4. `finally` 无论成功或中止都会关闭输出与负载。

可随时点 **停止**，引擎会在下一步前安全退出。演示环境把 `1000 ms` 的稳定等待加速到
`45 ms`，日志里会注明。

**判定规则**：实测过冲必须小于用户输入的限值；限值来自工作流且被锁定，
模型无法放宽。全部点位通过且最差过冲在限值内，总体才判 `PASS`。

## 6. 结果、报告与波形

底部区域包含：

- **结果表格**：每个点位的设定电压、实测电压、过冲、下跌、纹波、稳定时间与结论，
  外加 `最差` 行与 `限值` 行。
- **波形**：由最后一个点位的实测数据绘制的阶跃响应曲线，虚线标出实测过冲。
- **最差汇总**：最差过冲 / 纹波 / 稳定时间与限值对比。

导出按钮：

| 按钮 | 产物 |
| --- | --- |
| 导出 CSV | `testflow_RUN-XXXX.csv`，含 BOM，Excel 直接打开不乱码 |
| 导出报告 MD | `testflow_report_RUN-XXXX.md`，含结论、结果表、最差与限值对比 |
| 打印 / PDF | 调用浏览器打印，打印样式只保留结果区 |
| 一键复跑 | 用当前工作流再跑一次 |

导出的**语言跟随当前界面语言**；波形配色跟随当前主题。报告里的每个数字都来自运行记录，
不经过语言模型。

## 7. 历史与复跑

每次成功运行会在左栏「运行历史」留下一条记录，包含工作流名称、修订号、结论、
通过点数与运行编号。点击记录会载入**该版本的工作流快照**，随后点运行即可复跑同一套步骤。

历史保存在浏览器 localStorage（最多 12 条），不会上传到任何地方。

## 8. 语言与主题

右上角：

- **中文 / EN** — 界面、设备名、画布、日志、结果、导出报告、帮助页、浏览器标题一起切换；
  三条示例提示词也会换成对应语言。
- **主题按钮** — 深色 / 浅色切换，波形图同步换色。

选择会记住，刷新页面不会丢失；`<head>` 里有预置脚本，避免刷新时先闪一下深色。
测试意图输入框里**你自己改过的内容不会被切换覆盖**，只有仍等于示例原文时才会同步替换。

## 9. 常见问题

**Q：为什么「步骤 JSON」里还是中文？**
那是数据契约，不是界面文案。中文字段名被引擎、校验、历史快照和未来 LLM 输出共用，
跟着界面翻译会破坏已有工作流。展示层已经全部翻译了。

**Q：为什么只有模拟仪器？接真机要改什么？**
这是安全考虑：让原型不开箱就驱动带电设备。实现驱动适配器（见
[DEVELOPMENT.md](DEVELOPMENT.md)）即可，Planner 的 JSON 契约与 Engine 的事件协议不用改。

**Q：能改限值让它 PASS 吗？**
界面上可以编辑步骤参数，但限值来自用户输入并在工作流里标记 `锁定: true`；
`Planner.校验()` 会拒绝 `来源 !== 用户输入` 的工作流。AI 不能放宽限值，
也不能在没有运行记录的情况下声明 PASS。

**Q：数据存在哪？会上传吗？**
只有语言、主题、运行历史三项存在浏览器 localStorage。没有网络请求、没有遥测、
没有后端。导出的文件由浏览器直接下载。

**Q：怎么清空历史？**
浏览器开发者工具里执行 `localStorage.removeItem('testflow.history')` 后刷新。

**Q：为什么复跑结果和上次一样？**
模拟读数用确定性公式，保证「同一工作流复跑结果一致」的演示语义。真实仪器不会这样。

## 10. 注意事项

- 本项目是**参考原型**，不是生产级测试执行器，不要直接拿去控制贵重的被测设备。
- 接真机前请逐条核对编程手册、在假负载下验证、设置硬件保护并准备急停，详见
  [SECURITY.md](../SECURITY.md)。
- 提问或提 Issue 时请勿粘贴真实仪器地址、序列号与客户数据。
